This project uses a single control plane. For production ready, ideally the control plane should be at least three and is behind cloud Load Balancer or HA Proxy with keepalived and VIP

This project uses grafana cloud free tier. For production I will recommend either using paid tier Grafana or self host LGTM stack with S3 storage backend. Besides that a scraping interval of 60 seconds is used as a way to lessen telemetry load. Ideally scraping interval should be made smaller in real prodcution to ensure that observability telemetry has a more accurate resolution.

Why I use cloudflared tunnel. The primary reason why I use cloudflared tunnel as an alternative to AWS ALB is to save cost. CLoudflared tunnel is available for free tier users and it allows the exposure of kubernetes service without necessarily assigning public IP and port and configuring firewall ingress rules for it. The exposure is managed by the tunnel and the resources itself are exposed by making an egress connection to the tunnel. For this reason, all it needs are firewall egress rules to cloudflare IP addresses. This design makes it more secure since connection has to happen through cloudflare as middleman and no connection that bypass cloudflare is possible. Although cloudflared itself is not a load balancer, Kubernetes provides an internal load balancing functionality through its service API and since my cloudflared lives inside the kubernetes cluster, it can take advantage of kubernetes load balancing feature without necessarily taking additional risk by exposing the service to outside of the cluster.

As of the moment, I dont use NAT Gateway because NAT Gateway cost does not justify the functionality that it provides for this project scope. The service will be economically justified for a network with more internal resources in the network. Unfortunately at the moment, assigning each resource a public IP address is more economical in terms of cost. Of course this approach has a risk which is exposing our internal VPC resources with a publicly reachable IP. But this risk can be mitigated by ensuring that the resources are equipped with sufficiently restrictive security group rules to prevent unauthorized connection, both from external sources and internal sources.
